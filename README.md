# AI Sana

Локальный проект на JavaScript: Vite + Tailwind CSS на frontend и отдельный Node.js API.
Нужен Node.js 24 (либо совместимые версии из `engines` в `package.json`).

## Быстрый запуск

Из корня репозитория:

```bash
npm install
npm run dev
```

Интерфейс: http://localhost:3000, backend: http://127.0.0.1:3001.
`npm run dev` запускает оба процесса; остановка — `Ctrl+C` в терминале.
Регистрация, вход, задачи, отклики и промежуточная работа с AI используют Supabase.
Каталог показывает только реальные опубликованные задачи; новая база будет пустой.
Перед работой настройте окружение ниже и примените [миграции задач](docs/task-persistence.md).

Альтернативное имя той же команды:

```bash
npm run dev:full
```

Каталог всегда загружается через API, переключателя на демонстрационные данные нет.
Только frontend можно запустить через `npm run dev:web`, но для профиля, задач и AI ему нужен API.
Не запускайте `dev` и `dev:full` одновременно: они используют один порт.

## Структура

```text
apps/
  web/
    src/
      app/                  запуск, маршрутизация, состояние и события
      pages/                страницы, возвращающие HTML
      components/           общие элементы интерфейса и layout
      features/
        auth/               Supabase Auth, сессия и проверенный профиль
        tasks/              каталог, публикация, приватное автосохранение и AI-контроллеры
        proposals/          приватные отклики и решения бизнеса через API
      shared/               API-клиент, экранирование, уведомления, анимации
      styles/               Tailwind и существующие стили
    test/                   тесты frontend
  api/
    src/
      modules/auth/         проверка токена и загрузка профиля
      modules/tasks/        маршруты, сервис и repository задач
      modules/proposals/    сохранение откликов и разграничение доступа
      modules/task-analysis/ OpenAI: вопросы, формирование карточки и оценка
      shared/               HTTP-ответы и ошибки
      app.js                сборка HTTP-приложения
      server.js             запуск и остановка сервера
packages/
  contracts/                общий формат данных и проверки; фикстуры только для тестов
supabase/
  migrations/               SQL: профили, задачи, рабочие сессии и отклики
scripts/
  dev.js                    совместный запуск frontend и API
docs/
  architecture.md           правила расширения проекта
```

Проект использует npm workspaces: зависимости всех приложений устанавливаются одной командой
из корня. Общий `package-lock.json` фиксирует версии.

## Команды

| Команда                     | Назначение                                      |
| --------------------------- | ----------------------------------------------- |
| `npm run dev` / `npm start` | Frontend и backend вместе                       |
| `npm run dev:web`           | Только Vite, API запускается отдельно           |
| `npm run dev:api`           | Только backend, с перезапуском при изменениях   |
| `npm run dev:full`          | Frontend + API, каталог загружается с сервера   |
| `npm run build`             | Сборка frontend в `apps/web/dist`               |
| `npm run preview`           | Локальный просмотр готовой сборки на порту 3000 |
| `npm run check`             | ESLint, тесты всех пакетов и сборка             |
| `npm run format`            | Форматирование кода с Prettier                  |
| `npm run format:check`      | Проверка форматирования                         |

Другой порт frontend: `npm run dev -- --port 3002`.
Настройки API находятся в `apps/api/.env.example`; пример можно скопировать в `apps/api/.env`.

## Подключение backend

Для приложения заполните `apps/web/.env.local`:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
VITE_API_BASE_URL=/api
API_TARGET=http://127.0.0.1:3001
```

И `apps/api/.env` для того же Supabase-проекта:

```dotenv
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your-publishable-key
OPENAI_API_KEY=your-openai-api-key
OPENAI_MODEL=gpt-4.1-mini
```

Оба файла исключены из Git. Для Supabase достаточно publishable key
(для старых проектов поддерживается anon key); secret/service_role ключи не нужны и конфигурация их отклоняет.
OpenAI-ключ нужен для анализа и остаётся только в `apps/api/.env`, не во frontend.
В Supabase → Authentication → URL Configuration добавьте адреса локального приложения
`http://localhost:3000` и `http://127.0.0.1:3000` в разрешённые Redirect URLs.
Подтверждение email остаётся включённым: после регистрации перейдите по ссылке из письма.

В `apps/web/.env.example` перечислены настройки клиента. Для отдельного запуска приложений
запустите `npm run dev:api` и `npm run dev:web` в двух терминалах. Vite перенаправляет `/api`
на backend. Если меняете порт API, измените и `API_TARGET`.
`VITE_*` попадает в браузерный bundle, поэтому эти переменные не подходят для секретов.
После изменения `.env` перезапустите Vite; для production создайте новую сборку.

## База данных

В Supabase SQL Editor выполните миграции в таком порядке:

1. [Регистрация и profiles](supabase/migrations/20260923000100_registration_profiles.sql) — только если таблица профилей ещё не создана.
2. [Задачи и публичный каталог](supabase/migrations/20260923000200_tasks.sql).
3. [Приватные вопросы и ответы AI](supabase/migrations/20260923000300_task_workspaces.sql).
4. [Отклики студентов](supabase/migrations/20260923000400_proposals.sql).
5. [Принятие и отклонение откликов](supabase/migrations/20260923000500_proposal_decisions.sql).

Каждый файл выполняется один раз целиком под `postgres`. Миграции не удаляют старые данные
и не добавляют фиктивные задачи. Если `profiles` уже существует, начинайте со второго файла.
Ранее выполненные миграции повторять не нужно. Подробности и проверка доступа — в
[инструкции сохранения задач](docs/task-persistence.md) и [инструкции откликов](docs/proposals.md).

Исходное описание, вопросы и ответы AI, контакт заказчика доступны только владельцу.
Остальные поля опубликованной карточки становятся публичными: не вставляйте в них секреты.
«Мои задачи» показывает сохранённые черновики и публикации текущего пользователя.
Текущая рабочая сессия AI автоматически сохраняется отдельно и восстанавливается после обновления страницы;
перед закрытием дождитесь завершения синхронизации с Supabase.
При сохранении задачи её вопросы и ответы также архивируются в приватном `analysis_snapshot`:
начало новой задачи не стирает анкеты ранее сохранённых, их можно открыть через «Мои задачи».

## API

| Маршрут                                                       | Назначение / доступ                                                     |
| ------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/health`                                             | Проверка процесса API                                                   |
| `GET /api/tasks`                                              | Публичный каталог, `{ "data": Task[] }`                                 |
| `GET /api/tasks/:id`                                          | Публичная опубликованная карточка, `{ "data": Task }`                   |
| `GET /api/tasks/mine`                                         | Собственные задачи; Bearer-токен бизнес-пользователя                    |
| `POST /api/tasks`                                             | Сохранение черновика или публикация; Bearer-токен бизнес-пользователя   |
| `GET /api/task-workspace`                                     | Текущие приватные вопросы, ответы и карточка, либо `data: null`         |
| `PUT /api/task-workspace`                                     | Автосохранение приватного рабочего состояния; бизнес-пользователь       |
| `GET /api/proposals`                                          | Студенту — собственные отклики; бизнесу — отклики только на свои задачи |
| `POST /api/proposals`                                         | Отправка всех полей отклика на опубликованную задачу; только студент    |
| `PATCH /api/proposals/:id/decision`                           | Принять/отклонить отклик; только бизнес-владелец задачи                 |
| `GET /api/auth/me`                                            | Проверенные `user` и `profile`; Bearer-токен                            |
| `POST /api/ai/task-analysis/questions`, `/generate`, `/score` | AI-анализ; Bearer-токен бизнес-пользователя                             |

Все успешные ответы обёрнуты в `{ "data": ... }`. Приватное рабочее состояние требует
Bearer-токена и при чтении, и при записи. Читающие маршруты поддерживают `HEAD`. Ошибки имеют вид
`{ "error": { "code": "NOT_FOUND", "message": "..." } }` с соответствующим HTTP-статусом.
Если API недоступен, каталог показывает ошибку и кнопку повтора, а не подменяет ответ демоданными.

Сервер читает каталог из представления `published_tasks`, собственные задачи — из `tasks`,
текущую сессию — из `task_workspaces`. Приватные запросы используют пользовательский токен и RLS.
Если таблицы ещё не созданы, API сообщает об ошибке; перехода на фикстуры нет.
Подробности — в [описании архитектуры](docs/architecture.md) и [инструкции AI](docs/task-analysis.md).

## Текущие границы

Регистрация, вход, подтверждение email, восстановление сессии и выход подключены к Supabase.
Профиль и роль backend читает из `profiles` после проверки токена через Supabase Auth.
Кабинет недоступен до успешной проверки; при ошибке сети проверку можно повторить.
Задачи, черновики, вопросы, ответы и результаты AI сохраняются в Supabase после применения миграций.
Отклики сохраняют команду, идею, план, срок и ссылку; студент видит их в «Мои отклики»,
а владелец задачи — в «Отклики». Обновление страницы или кнопка «Обновить» загружает данные из базы.
На одну задачу студент может отправить один отклик; повтор запроса не создаёт дубликат.
Бизнес может принять или отклонить отклик и изменить решение позднее; студент видит
сохранённый статус и дату решения в «Мои отклики». Решение не закрывает задачу и не меняет
остальные отклики. Редактирование текста отправленного отклика пока не реализовано.
OpenAI выполняет настоящий анализ через backend. Избранное ещё не подключено к постоянному
хранению и остаётся локальным. Раздел «Моя команда» удалён; название команды указывается в отклике.
Восстановление пароля через письмо пока не реализовано.

Страницы остаются на обычном JavaScript, без React. Tailwind доступен в HTML-шаблонах;
Preflight отключён для сохранения существующего оформления. Старые стили находятся в слое `components`,
поэтому utility-классы Tailwind могут их переопределять. Шрифт Manrope загружается из Google Fonts;
без интернета используется системный шрифт.

`vite preview` предназначен для локальной проверки. При публикации раздавайте `apps/web/dist`
и настройте перенаправление `/api` к серверу на уровне хостинга или reverse proxy.
Vite-конфигурация не переносится в статическую production-сборку.
