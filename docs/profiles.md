# Профили участников

Выполните `supabase/migrations/20260923000300_profile_settings.sql` в Supabase SQL Editor после существующей миграции регистрации. Повторное выполнение допускается. В рабочий Supabase миграция автоматически не отправлялась.

Профиль: `#/profile` — открывается по кнопке аккаунта слева внизу (на мобильном экране — в шапке). Чужой профиль: `#/profile?user=<uuid>`. Список с поиском по имени и страницами по 24 участника: `#/members` (ссылка в профиле). Просмотр требует входа; ссылка на чужой профиль восстанавливается после входа в рамках открытой страницы.

В профиле сохраняются имя, специализация, организация, город, описание, навыки через запятую и HTTPS-ссылки LinkedIn, Instagram, GitHub, Telegram, сайта/портфолио. Сведения видны зарегистрированным участникам. Email берётся только из собственной сессии, не из публичных полей профиля. Роль не редактируется. Незавершённое редактирование не сохраняется при уходе со страницы.

Фото JPG/PNG/WebP до 5 МБ обрезается по центру до квадрата 512×512 и перекодируется в JPEG перед отправкой. Хранилище `profile-avatars` приватное; просмотр через подписанные ссылки на час, запись и удаление только в папке владельца. Фото можно заменить или удалить. При ошибке записи пути новая загрузка удаляется, прежняя фотография сохраняется. При сбое удаления старого объекта он может остаться в хранилище и потребовать административной очистки. Удаление аккаунта также требует очистки Storage.

Используется существующий браузерный Supabase-клиент с пользовательской сессией; service role не нужна. SQL расширяет `profiles`, разрешает чтение участникам, сохраняет ограничения на UPDATE владельцем и неизменяемость роли. Основа правил Storage: [официальная документация Supabase](https://supabase.com/docs/guides/storage/security/access-control).

Проверки: тесты в `apps/web/test/profiles.test.js`; миграция выполнена повторно в изолированном PGlite с проверками RLS, ограничений URL, длины полей, владельца аватара, запрета анонимного чтения и смены роли. Работа с реальным Supabase требует применения SQL; браузерная проверка загрузки в рабочее хранилище не выполнялась.
