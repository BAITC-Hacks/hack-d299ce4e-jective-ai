# Документы и скриншоты для бизнес-задачи

## Включение в Supabase

В SQL Editor вашего проекта выполните целиком:
`supabase/migrations/20260923000200_task_attachments.sql`.

Скрипт требует существующую таблицу `public.profiles` из миграции регистрации.
Он создаёт только таблицу `task_attachments`, приватный Storage bucket
`task-attachments`, индекс, лимит пяти файлов на черновик и RLS-политики.
Существующие таблицы задач, профилей и Auth не изменяются. Скрипт допускает
повторный запуск. В рабочий Supabase он автоматически не применялся.

Используются уже настроенные `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`
(либо `SUPABASE_ANON_KEY`), `OPENAI_API_KEY` и `OPENAI_MODEL` на API-сервере,
а также публичные VITE-настройки авторизации. Service-role ключ не нужен.
Код работает в рамках JWT пользователя и проверяет бизнес-роль через существующий
authService. Frontend передаёт актуальный токен из сессии Supabase.

## Как пользоваться

1. Войти как бизнес и открыть «Создать задачу».
2. Выбрать файлы, перетащить их в область загрузки либо вставить скриншот из
   буфера через Ctrl+V. До пяти файлов, каждый до 10 МБ.
3. Дождаться загрузки и чтения OpenAI. Поддерживаются PDF, DOCX, XLSX, TXT/CSV
   в UTF-8, PNG, JPEG и WebP. Исходные файлы сохраняются в приватном Storage.
4. Открыть «Что извлечено из файла»: краткое содержание, факты с указанием
   источника и предупреждения. Непрочитанные файлы не включаются молча.
5. Галочкой выбрать файлы для анализа. Ненужные можно исключить без удаления.
   Доступны повтор обработки, скачивание и удаление оригинала вместе с метаданными.
6. Описать цель или оставить описание пустым, если задача ясна из материалов.
   Нажать «Проанализировать с AI». Прикреплённые факты используются при составлении
   вопросов и итоговой карточки. Уточнения и публикация остаются ручными действиями.

Список выбранных источников фиксируется при начале анализа, виден на дальнейших
шагах и в редакторе. Для изменения набора вернитесь к описанию и повторите анализ.
Короткое описание допускается, когда есть выбранные обработанные файлы.

## Хранение и доступ

Путь оригинала: `<owner_id>/<draft_id>/<attachment_id>.<extension>`.
Клиентские имена не используются как пути. Bucket ограничивает MIME и размер,
сервер проверяет расширение и сигнатуру/кодировку. Исходники не перезаписываются.
Каждый бизнес видит только свои материалы; студентам и анонимным пользователям
доступ запрещён. Скачивание выдаёт короткую подписанную ссылку на 60 секунд.
Ссылку до истечения срока может использовать любой, кому её передали.

Метаданные и извлечённый контекст сохраняются в `task_attachments`. В localStorage
находится только UUID текущего набора вложений, отдельно для каждого пользователя.
Поэтому материалы восстанавливаются после перезагрузки в том же браузере. Это не
автосохранение всей формы: текст описания, ответы и карточка пока остаются в session
store. Очистка localStorage теряет указатель на набор, но не удаляет файлы из Storage.
Для старых наборов при необходимости используйте Storage Dashboard.

После «Принять результат» интеграционные ссылки доступны в
`state.acceptedAttachmentIds` и `state.attachmentDraftId`. При будущем сохранении
реальной задачи необходимо сохранить этот набор ссылок вместе с её записью.
Существующий демонстрационный submit задач не заменён реализацией новой таблицы задач.
Файлы не публикуются в каталоге и не становятся доступны студенческим командам.

Удаление через UI вызывает Storage API, затем удаляет метаданные. При сетевом
сбое операция допускает повтор. Удаление аккаунта через Auth каскадно удаляет
метаданные; очистку оставшихся Storage-объектов для удалённых аккаунтов следует
включить в административную процедуру удаления аккаунта.

## AI и ограничения

Original → OpenAI Responses → `{summary, facts:[{text,source}], warnings}`.
Изображения передаются как `input_image`; PDF/DOCX/XLSX — `input_file`; TXT/CSV —
как текст до 100 000 символов. Модель получает запрет выполнять инструкции из файлов
и придумывать факты. Результат проверяется по схеме и размеру. Для XLSX явно
показывается предупреждение об ограниченном охвате строк. Защищённые паролем,
повреждённые и нечитаемые документы могут потребовать PDF или отдельного скриншота.
Распознавание — помощь пользователю, а не гарантия достоверности.

Для вопросов и карточки браузер передаёт только IDs. API проверяет владельца и
загружает извлечённый контекст под RLS; клиентские `attachedDocuments` игнорируются.
Вложения и извлечённые данные считаются пользовательскими источниками, а не
инструкциями или независимо подтверждёнными фактами. OpenAI вызывается с `store:false`.

## API

- `GET /api/task-attachments?draft=<uuid>` — материалы черновика.
- `POST /api/task-attachments?draft=<uuid>&name=<encoded filename>` — бинарный
  файл с Content-Type `application/octet-stream`.
- `POST /api/task-attachments/<id>/analyze` — извлечение и сохранение контекста.
- `GET /api/task-attachments/<id>/download` — временная ссылка.
- `DELETE /api/task-attachments/<id>` — удаление оригинала и метаданных.
- `POST /api/ai/task-analysis/questions|generate` — дополнительно `attachmentIds`.

Все операции с вложениями требуют Bearer JWT бизнес-пользователя. Ответы сохраняют
общий envelope `{data}` / `{error:{code,message}}`.

## Проверено

- `npm run check`: lint, автотесты, production build.
- Изоляция владельцев, анонимный/студенческий доступ, права колонок, лимит файлов
  и повторное применение SQL проверены в локальном PostgreSQL-движке PGlite
  с эмуляцией схем Auth/Storage. Это не проверка развёрнутого Supabase Storage.
- Реальные запросы OpenAI для PDF, DOCX, XLSX, TXT, CSV и PNG; цепочка документа
  до вопросов и карточки. Live Supabase upload требует выполнения SQL пользователем.
- Тесты состояний загрузки, повторов, восстановления, исключения, удаления,
  экранирования текста и защиты от поздних ответов другой сессии.

Документация: https://developers.openai.com/api/docs/guides/file-inputs
и https://supabase.com/docs/guides/storage/security/access-control
